HWK QIP Incentive System — AQL Allowance New Feature Guide

Issued: 2026-05-04  |  Audience: Quality Department / Incentive Operations

Summary: When you register an AQL-rejected PO with a valid reason, the system automatically exempts the affected employees' incentive conditions (C5~C8) and recalculates incentives. Administrators only enter PO numbers — the system automatically identifies affected employees and computes incentive changes.

1. Why this feature?

Previously, when an AQL Reject occurred, all employees who inspected that PO had their C5~C8 conditions marked as NO and lost their incentive eligibility. However, if the reject was caused by factors outside the employee's control (raw material defect, equipment malfunction, external causes), the department head must be able to grant exemptions at the PO level.

3. How to Use AQL Allowance

  1. Open Admin page → "AQL Allowance" tab
  2. Select Month / Year (the month the PO was inspected)
  3. Type PO number(s) and press Enter (e.g., 902078209, 902225040)
  4. Enter Root Cause (e.g., "Surface defects caused by raw material issue")
  5. Enter Action Plan + Due Date (e.g., "Request supplier corrective action + strengthen incoming inspection" / 2026-05-31)
  6. Optional: attach photos/documents (max 3 files, ≤2MB each)
  7. Confirm exempt condition checkboxes (default: C5/C6/C7/C8)
  8. Click [Preview Affected Employees] → system shows matched rows, FAIL count, total reject qty, employee list with Before/After incentive changes
  9. Click [Apply AQL Allowance] after review → affected employees' incentives recalculated automatically

4. Automated Processing

  • Auto employee identification: Extracts employee numbers from all matched AQL inspection rows
  • C5~C8 auto-recalculation:
    • C5 (Personal AQL FAIL): PASS if employee's FAIL count becomes 0 after PO exemption
    • C6 (Consecutive AQL): Treated as exemption candidate if this month's C5 becomes PASS
    • C7 (Team/Area): Exempted if own C6 is exempted
    • C8 (Area Reject Rate): Building-level reject rate recalculated; exempted if below threshold
  • Incentive recalculation: If pass rate reaches 100% after exemption, incentive auto-computed via progressive table (TYPE-1) or Position multiplier (TYPE-2)
  • Dashboard auto-refresh: Blue "AQL Allowance" badge appears next to C5~C8 rows in employee modal; KPI cards update immediately
  • Pipeline protection: Registered AQL Allowances are auto-reapplied after every hourly pipeline run, preventing data overwrites

5. Action Plan Tracking

Each registered PO Allowance includes an action plan and due date. The action status (Planned / In Progress / Completed) can be updated from the admin page. The employee modal also shows the action plan progress for all affected employees.

6. Data Integrity Guarantees

  • Original preservation: Original conditions, pass_rate, and incentive are saved as a snapshot at apply time → 100% restoration on Revoke
  • Audit trail: Applied-by email, timestamp, revoked-by, and revoke reason are all recorded
  • Duplicate prevention: The system blocks re-registration of the same PO
  • Permission separation: Firestore rules ensure regular users have read-only access; only admins can write
